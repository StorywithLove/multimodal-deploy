## Transformers 单次生成与保存

认证任务要求：用 Qwen3-8B、Transformers 生成超过 100 字符的小说，保存到 `/data/exam/text_inference.txt`。模型负责生成字符串，Python 负责写文件；提示模型“保存到路径”不会使普通 `generate()` 自动获得文件写入能力。

Notebook 中如缺 Accelerate，使用当前内核的 pip 安装，完成后重启内核：

```python
%pip install accelerate
```

以下是依据对话流程整理的复现参考，完整脚本未在本地执行；应以云端实际输出检查字符数和考核要求：

```python
from pathlib import Path
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_name = "/mnt/moark-models/Qwen3-8B"
tokenizer = AutoTokenizer.from_pretrained(model_name, local_files_only=True)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype="auto",
    device_map="auto",
    local_files_only=True,
)

messages = [{
    "role": "user",
    "content": "请创作一篇约300字的科幻短篇小说，直接输出正文。",
}]
text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
    enable_thinking=False,
)
inputs = tokenizer(text, return_tensors="pt").to(model.device)
with torch.inference_mode():
    output = model.generate(**inputs, max_new_tokens=1024)
content = tokenizer.decode(
    output[0, inputs.input_ids.shape[1]:],
    skip_special_tokens=True,
).strip()

if len(content) <= 100:
    raise ValueError(f"正文不足要求：{len(content)} 字符，请重新生成")
path = Path("/data/exam/text_inference.txt")
path.parent.mkdir(parents=True, exist_ok=True)
path.write_text(content, encoding="utf-8")
print(path, len(content))
```

要点：只解码新生成的 token，避免把输入提示词写进正文；保存使用 UTF-8。`mkdir(parents=True, exist_ok=True)` 创建父目录，写文件会覆盖同名文件。`device_map="auto"` 负责设备分配，dtype 控制数值格式，两者含义不同。

## vLLM：一条命令启动服务

前提是选用了已适配的镜像，且权重目录存在。一条命令简化的是服务启动，底层驱动、框架与算子适配已由镜像提供。

```bash
vllm serve /mnt/moark-models/Qwen3-0.6B --port 8188
```

切换 8B 时先停止前一个服务，再执行：

```bash
vllm serve /mnt/moark-models/Qwen3-8B --port 8188
```

成功标志：

```text
Platform plugin metax is activated
Starting vLLM server on http://0.0.0.0:8188
Application startup complete.
```

启动成功还不等于请求成功，应继续检查 `/v1/models` 并发送实际生成请求。

### 坑：模型已启动，请求却返回 404

原始错误：

```text
The model `Qwen3-8B` does not exist.
POST /v1/chat/completions ... 404 Not Found
```

原因：没有设置别名时，该次服务注册的名称是完整路径 `/mnt/moark-models/Qwen3-8B`，请求却用了 `Qwen3-8B`。与权重文件缺失、GPU 适配和显存容量无关。

解决方式二选一：

1. 不重启服务，将 JSON 中的 `model` 改为完整路径。
2. 重启时显式设置别名，让请求使用短名称。

```bash
vllm serve /mnt/moark-models/Qwen3-8B \
  --port 8188 \
  --served-model-name Qwen3-8B
```

在服务器另一个终端验证，以下请求对应已经设置别名的启动命令：

```bash
curl http://127.0.0.1:8188/v1/models

curl --fail-with-body http://127.0.0.1:8188/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "Qwen3-8B",
    "messages": [{"role": "user", "content": "请写一篇约300字的科幻小说。"}],
    "max_tokens": 1024,
    "chat_template_kwargs": {"enable_thinking": false}
  }'
```

### 启动日志的资源观察

| 项目 | Qwen3-0.6B | Qwen3-8B |
|---|---:|---:|
| 权重加载占用 | 1.12 GiB | 15.27 GiB |
| KV Cache 可用空间 | 约 26.17 GiB | 约 11.4 GiB |
| 日志中的设备总显存 | 约 30.84 GiB | 约 30.84 GiB |
| 最大模型长度 | 40960 token | 40960 token |

这些是初始化日志观察，不是性能排名或全部运行峰值。vLLM 会预留大量显存作为 KV Cache，小模型也可能看到较高总占用。FP16 与 BF16 都是每个数 2 字节，互换通常不能大幅降低权重占用。

`fla package is not installed`、部分候选注意力后端不可用，以及采样参数被 `generation_config.json` 覆盖，在本轮没有阻止启动；优先看最后的异常和实际选用后端，不将每条 WARNING 都视为失败。

## SSH 隧道访问

服务器内部访问 `127.0.0.1:8188`；本地电脑需要通过平台 SSH 入口转发。用户名、地址和 SSH 端口从工作台复制，不使用文档示例凭据。

在本地 Windows PowerShell 执行，替换占位信息：

```powershell
ssh -N -L 127.0.0.1:9000:127.0.0.1:8188 用户名@主机地址 -p SSH端口
```

保持隧道终端打开，在本地另一个终端验证：

```powershell
curl.exe http://127.0.0.1:9000/v1/models
```

本地 Base URL 为 `http://127.0.0.1:9000/v1`。第一个回环地址属于本地电脑，第二个属于远端 SSH 会话可达环境；SSH 端口、远端 API 端口和本地端口是不同概念。隧道不会启动模型，也不会把模型计算转移到本地。
